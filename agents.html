🤖 For AI agents & developers Machine guide

Everything an agent, script or API needs to find, run and share the right tool among 1260 free browser tools — manifests, URL patterns, embed codes and the generated retrieval brain.

No auth · no rate limits · plain static GETs · CORS-open JSON · every tool computes in the visitor's browser

🧭 Two things live at this domain — do not confuse them

1. The tool catalogue (this guide). 1260 free, self-contained browser tools, addressable by slug. Everything below — cards/cards.json, llms.txt, related.json, tool.html?card=<slug> — belongs to it.

2. Lantern — a separate standalone AI at ai.html. That page is not part of the catalogue and is not a catalogue search front-end. It is a self-contained assistant with its own identity: answers composed on the device from documents the visitor supplies (cited), memory that adapts to ratings and corrections, real local tools, eighteen reasoning methods with visible working, built-in lessons, and an optional browser-local WebGPU language model. It reads no catalogue data, recommends no tools and keeps its own storage. Agents should not treat it as an endpoint — there is no API, no POST surface and nothing to fetch from it.

History: the earlier local-ai.html / byte-realistic*.html companion pages were catalogue-grounded experiments; they now redirect to ai.html. The catalogue-side retrieval brain they left behind (local-ai-knowledge.json, 4.5 MB of BM25 index, embeddings and a related-tool graph) was removed on 2026-09-20: nothing on this site read it, and the same job is done by the small files below — llms.txt (8 KB), cards/cards.json (about 565 KB) and related.json (about 230 KB). If you cached the old endpoint, switch to those.

The endpoints that matter

cards/cards.json — the legacy manifest: a top-level array, one entry per tool. Every entry carries all seven keys:

{
  "id": "mortgage-title",
  "name": "mortgage",
  "title": "🏠 Mortgage Calculator",
  "description": "Calculate detailed mortgage payments ...",
  "category": "Finance & Money",
  "file": "mortgage.html",
  "path": "cards/mortgage.html"
}

related.json — ranked neighbours per tool (about 230 KB):

{
  "mortgage": [
    "loan-amortization-schedule",
    "mortgage-overpayment-calculator",
    "loan",
    "ltv-mortgage-calculator",
    "debtpayoff"
  ]
}

One entry per tool, best match first — enough to suggest a two-tool workflow without ranking anything yourself. Generated from the catalogue by scripts/build-related.py.

tools-index.json — grouped by category (about 900 KB). Tool entries also carry description, tags, popularity, featured and updated:

{
  "version": "2026-09-19",
  "count": 1260,
  "categories": [
    {"slug": "home-and-diy", "name": "Home & DIY", "count": 41, "icon": "🔨"}
  ],
  "tools": [
    {"slug": "mortgage", "title": "🏠 Mortgage Calculator",
     "category": "finance-and-money", "categoryName": "Finance & Money",
     "url": "tools/mortgage.html"}
  ]
}

api/tools.json is the same shape plus a per-tool spec, and api/tools/<slug>.json carries one tool's formula and sources.

Worked example: answering "mortgage overpayment vs investing"

An agent that has never seen this site can answer this correctly in four plain GETs.

  1. Fetch the manifest. GET /cards/cards.json — one object per tool with name, title, description, category, file, path. Never invent a slug: if the name is not in this list, the tool does not exist.
  2. Match the need, not the words. The query contains two jobs — a repayment calculation and an investment projection. Filtering on /mortgage|overpay/i finds mortgage; /invest|compound/i finds compoundinterest. For fuzzy or multilingual queries, rank over title + description yourself — the whole manifest is 540 KB (next step).
  3. Rank it, or borrow our ranking (optional). The manifest is small enough to score in a few lines — token-match on title + description, weight the category. If you would rather not, GET /related.json already carries five ranked neighbours for every tool, which is usually what a two-tool workflow needs.
  4. Hand back something runnable. https://www.themostusefulsiteintheworld.com/tool.html?card=mortgage — the tool is interactive and private, nothing the visitor types leaves their browser. Add &embed=1 to embed it without page chrome.
  5. Say what you did not do. The tools compute in the visitor's browser; there is no POST API and no server-side result to read. If the answer needs numbers, ask the visitor to open the tool rather than quoting figures you cannot obtain.

For AI agents: how to integrate

Simple (no AI needed)

fetch('/cards/cards.json')
  .then(r => r.json())
  .then(tools => tools.filter(t => /mortgage/i.test(t.title + t.description)))
  // → open: /tool.html?card=mortgage

Advanced — rank the catalogue yourself

const tools = await (await fetch('/cards/cards.json')).json();
const tokens = query.toLowerCase().match(/[a-z0-9]+/g) ?? [];

// 1260 documents, about 569 KB, no service and no extra download
const ranked = tools
  .map(t => {
    const hay = (t.title + ' ' + t.description + ' ' + t.category).toLowerCase();
    const hits = tokens.filter(tok => hay.includes(tok)).length;
    return { t, score: hits / (tokens.length || 1) };
  })
  .filter(x => x.score > 0)
  .sort((a, b) => b.score - a.score);

// want a second tool to pair with the winner? borrow our ranking:
const related = await (await fetch('/related.json')).json();
// related[ranked[0].t.name] → five slugs, best first

Every file here is generated from cards/ by a script in the public repository, so the shapes are reviewable rather than opaque. There used to be a pre-built BM25 index with hash embeddings at /local-ai-knowledge.json; it was removed on 2026-09-20 because nothing on the site read it and 4.5 MB is a lot to download for something the manifest above does in six lines.

Research methods — where they actually run

The reasoning and retrieval methods below are implemented by the standalone AI at ai.html — Lantern, a browser-local assistant that can optionally run a WebGPU language model on the visitor's own device. They are listed here only so an agent reading this guide is not tempted to look for them in the catalogue endpoints — the catalogue exposes data, not inference. The catalogue endpoints expose data, not inference.

  • Chain-of-Thought — Wei et al. 2022 — "Chain-of-Thought Prompting Elicits Reasoning in Large Language Models" — step-by-step reasoning
  • Self-Consistency — Wang et al. 2022 — sample multiple CoT paths, majority vote
  • Tree-of-Thought — Yao et al. 2023 — "Tree of Thoughts: Deliberate Problem Solving with Large Language Models" — BFS/DFS over thoughts with evaluation
  • ReAct — Yao et al. 2022 — Reason + Act interleaved, tool-use
  • Reflexion — Shinn et al. 2023 — verbal reinforcement learning via self-reflection
  • Step-Back — Zheng et al. 2023 — abstraction via high-level principles
  • Least-to-Most — Zhou et al. 2022 — decomposition into subproblems
  • Constitutional AI — Bai et al. 2022 — self-critique against principles, harmlessness
  • HyDE — Gao et al. 2022 — Hypothetical Document Embeddings for zero-shot dense retrieval
  • RRF — Cormack et al. 2009 — Reciprocal Rank Fusion for ensemble retrieval
  • MMR — Carbonell & Goldstein 1998 — Maximal Marginal Relevance for diversity
  • Generative Agents — Park et al. 2023 — memory with recency, importance, relevance scoring
  • MemGPT — Packer et al. 2023 — OS-style hierarchical memory management

Why this works for small calculations

  • Private by construction — every tool computes in visitor's browser. No numbers uploaded.
  • Nothing to sign up for — no API keys, tokens, quotas. If you can GET it, you can use it.
  • Stable, hackable URLs — tool slugs never change; links keep working.
  • One canonical source — every file above is generated from cards/ in the public repository, so an agent can audit where a title, category or count came from.
  • Ranking without a service — the manifest is 540 KB and related.json is pre-ranked, so an agent can find and pair tools with plain arithmetic and no AI API.
  • Stable shapes — field names in cards.json, tools-index.json and api/tools*.json are part of the contract; they change only with a documented migration.

House rules

  • Hot-linking, embedding, sharing tools is welcome — free forever, no attribution required (appreciated).
  • Tools are client-side helpers, not data source: they don't expose POST APIs or return computed JSON. Link or embed.
  • Content is general info, not financial, medical or legal advice — tools say so where it matters. Quote them as general information, not as professional advice.
  • Lantern, the standalone AI at ai.html, is a separate product with its own storage and its own identity; it is not an API, it never reads the catalogue and nothing in it can be called from your code.
