Tips for readable code images, and how the highlighting works

Keep it short. The images that get read are 5–25 lines long with one idea in them. Trim imports and boilerplate, and use Highlight to point at the lines that matter — a comma-separated list with ranges, like 3, 7-9. A title in the frame ("api/routes.ts") gives the snippet context without a caption. Long lines wrap at the column you choose so nothing is cut off; turn wrapping off if the exact line breaks matter.

Export at 2×. Social sites downscale images, and code with thin glyphs turns to mush at 1×. The 2× export draws every glyph at double resolution, which stays sharp on phones and high-density screens; 3× is for slides and print. Copy image puts the PNG on the clipboard for pasting straight into Slack, a doc or a tweet composer (recent Chrome, Edge and Safari on a secure page); the download works everywhere.

How the highlighting works. A small tokenizer runs in the page — no external library and no server. It recognises comments, strings (including template literals and Python triple quotes), numbers, language keywords, function calls, capitalised type names, and for HTML, CSS, JSON and YAML the tags, attributes, selectors, properties and keys. Auto-detect looks for tell-tale syntax (a def, a <div, a SELECT, a fn main) and falls back to JavaScript-style colouring, so pick the language yourself if it guesses wrong. It is not a full parser: exotic syntax may be coloured plainly, which is still perfectly readable.

Themes and fonts follow the well-known editor palettes (Dracula, One Dark, Night Owl, Monokai, Nord, GitHub Light, Solarized Light) and use whichever monospace font your device has — JetBrains Mono, Fira Code, Menlo, Consolas or the system default — so the image matches what you see. Your snippet and settings are kept in this browser only, so a refresh does not lose them; the share link carries the code itself, compressed into the address.
