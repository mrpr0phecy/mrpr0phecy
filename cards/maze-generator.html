The four algorithms, choosing a difficulty, codes and batches, SVG for cutting

Perfect mazes. With loops set to none, every maze here is a “perfect” maze: a spanning tree of the grid, so there is exactly one route between any two cells and no way to go round in circles. The entrance is cut into the top-left wall and the exit into the bottom-right, and the solution shown is the unique path between them. Braiding knocks down walls at dead ends to create loops, which makes a maze feel more like a labyrinth and, counter-intuitively, often easier, because wrong turns rejoin the main path.

Algorithms. The recursive backtracker (depth-first search) produces long, winding corridors with few branches — the classic hard maze that looks like a river system. Prim’s algorithm grows the maze from a frontier and gives lots of short dead ends, a stubby texture that is quick to solve but busy on the page. Kruskal’s algorithm joins random walls with a union-find structure and sits between the two. The binary tree carves either north or east from every cell, which creates an unmistakable diagonal bias and two long straight outer corridors; it is the easiest style and good for young children.

Difficulty. Size dominates: a 10 × 10 backtracker maze takes a child a minute, 30 × 30 is a coffee-break, 60 × 60 fills a whole page with corridor and takes real patience. The figures under the preview — solution length as a share of all cells, and the number of dead ends — are a fair guide: a long solution with many dead ends is hard.

Codes and batches. Each maze is generated from its code, so the same size, style and code always give the same maze; note the code and you can print the answer later, or set a class the identical puzzle. A batch PDF uses the code followed by -2, -3 and so on for the extra pages, with the answer pages after the puzzles. SVG saves the walls as a single stroked path in millimetres, ready for a plotter, laser cutter or vinyl cutter, and it stays sharp at any size.
