# Shared project notes

This directory stores durable, topic-based knowledge that any future AI or
human contributor can improve. These are **not staff roles, assignments,
personalities, conversations or a coordination board**. Nobody “owns” a topic.

## Collections

- [`design.md`](design.md) — visual systems, accessibility and responsive UI
- [`catalogue.md`](catalogue.md) — cards, generation, safety and tool quality
- [`seo.md`](seo.md) — metadata, indexing, structured data and discovery
- [`music.md`](music.md) — MrProphecy pages, verified media and listener journeys
- [`operations.md`](operations.md) — verification, deployment and repository hygiene

Use `ARCHITECTURE.md` for current facts and hard implementation rules,
`ROADMAP.md` for work still to do, and these collections for observations,
experiments and reusable lessons.

## How to add a note

Append under the relevant collection's **Field notes** heading:

```markdown
### YYYY-MM-DD — Short descriptive title

**Context:** What was examined or changed.

**Finding:** What another contributor should know.

**Evidence:** File names, commands, measurements or links that support it.

**Follow-up:** Optional next step. Put actionable work in `ROADMAP.md` too.
```

Guidelines:

1. Write about the project, not about yourself or an invented job title.
2. Prefer measured findings over opinions; include reproducible evidence.
3. Do not paste credentials, private analytics, personal data or chat logs.
4. Do not use notes to claim files, command other conversations or record
   fictional owner approval.
5. Correct stale notes explicitly rather than silently building on them.
6. Keep binding rules in `ARCHITECTURE.md` and outstanding tasks in
   `ROADMAP.md`, so these notes cannot become a second hidden rulebook.
